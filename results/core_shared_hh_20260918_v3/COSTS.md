# 更新预算、通信量与实测时间

下表先累计每次 30 轮训练的费用，再取五个种子的平均。一个组件包含同层 query/value 两个投影中同编号的 rank 分量；每次只更新 A、B 两个因子之一。分类头每次更新 1538 个参数，另外记录。

|方法|组件更新次数|下载 GiB|上传 GiB|总 GiB|评分秒数|客户端训练秒数|
|---|---|---|---|---|---|---|
|PCLA|17398.4|0.665331|0.103793|0.769124|19.588|259.169|
|随机组件|17398.4|0.665331|0.103760|0.769091|0.000|242.256|
|按重要性选整层|17398.4|0.665331|0.102892|0.768222|16.582|165.087|
|固定层和数量、随机组件编号|17398.4|0.665331|0.103793|0.769124|0.000|245.264|
|随机选整层|17398.4|0.665331|0.102891|0.768222|0.000|195.453|
|均匀轮换组件|17398.4|0.665331|0.104940|0.770271|0.000|275.633|
|只训练分类头|0.0|0.665331|0.002474|0.667805|0.000|101.265|
|更新全部组件|57600.0|0.665331|0.335286|1.000617|0.000|235.083|

GiB = 2³⁰ 字节。通信量根据实际发送内容的序列化大小计算：下载完整的当前 LoRA 和分类头，上传被更新因子的参数增量、分类头和位置记录。预先缓存的基础模型、数据文件、保存模型状态及取回结果的流量另存于执行档案。

评分时间是在客户端训练样本上计算重要性的时间，每次使用 16 条样本。训练时间记录客户端更新参数的计算。实验在 RTX 4090 上逐个模拟客户端，各方法分布在不同节点和执行阶段；此处呈现本次实测费用。

“固定层和数量、随机组件编号”需要先读取同种子 PCLA 的选择记录。表中是该对照自身的费用；生成记录的 PCLA 还需要平均 0.769124 GiB 通信量、259.169 秒训练和 19.588 秒评分。两次运行合计约 1.538248 GiB、524.021 秒训练加评分。

PCLA 累计组件更新数量约为全部组件参照的 30.2%，训练加评分约 278.757 秒，全部组件参照约 235.083 秒。这次实现中，减少更新组件并没有带来相应的时间节约。
