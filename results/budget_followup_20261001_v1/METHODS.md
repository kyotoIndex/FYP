# 方法与读数说明

这份说明补充 [README](README.md) 没有展开的细节：数据怎样切分、每种方法具体怎么做、主要数字怎么算，以及数据文件里的方法编号分别对应什么方法。

## 1. 数据切分

三部分都只使用 SST-2 官方训练集。先把完全相同的句子（统一大小写、空白和 Unicode 写法后相同）归成一组，同一组只进入同一部分，再切成互不重叠的几部分：

| 部分 | 数量 | 用途 |
|---|---:|---|
| 客户端训练 | 50 × 256 = 12,800 | 客户端本地训练 |
| 客户端本地读数 | 50 × 64 = 3,200 | 诊断用，训练和方法选择都不读取 |
| 公共训练数据 | 512 | 服务器可用；第一部分只给原生方法和共享方向诊断，第二部分给服务器控制、服务器上训练分类头、FedLAW、Fed-SB 初始化 |
| 诊断选择集 | 1,024 | 第一部分诊断中“从候选里挑最好组合”时使用 |
| 诊断读数集 | 2,048 | 两部分诊断的最终读数 |
| 配方开发与验证评价 | 4,096 | 所有准确率和损失的评价集 |

客户端先按 constrained Dirichlet α=0.3 分到 320 条，再在每个客户端内按标签分层切成 256 条训练和 64 条本地读数。每个种子有自己的客户端划分、初始化和参与顺序；同一种子下所有方法共用这些设置。具体样本编号见 [reproduce/data_manifest/](reproduce/data_manifest/)。第二部分在第一部分的清单上为新种子追加了划分，原有种子的记录不变。

评价集用于开发阶段挑配方，也用于验证阶段读数；验证阶段换用新的种子，所以验证数字反映的是换随机性后的表现，它不是完全没见过的测试集。

## 2. 共同训练设置

- 模型：BERT-base-uncased，最大长度 64，FP32；LoRA 加在每层注意力的 query 和 value 上，缩放系数 1，dropout 0.1。
- 每轮：50 个客户端里均匀随机抽 10 个；每个客户端本地 1 个 epoch，batch 16，共 16 步；每次参与都重新建 AdamW（betas 0.9/0.999，weight decay 0.01）。
- 聚合：按参与者等权平均。部分更新的方法中，客户端没有更新的位置按 0 计入。
- 通信：按程序实际编码的上传和下载字节计，包括控制消息和失败后已经发出的消息。
- 通信额度：完整 rank8 LoRA 跑 100 轮的实际字节数，2,382,653,750 字节。另外记录一半额度时的读数。
- 返回模型：额度用完时最后一个完整的全局模型。至少观察到第 100 轮；额度没用完的方法最多跑到第 200 轮。额度用完之后继续跑的轮次只用于看曲线，不计入成绩。
- 初始化：不同 rank 的 LoRA 用同一个随机矩阵的前 r 行初始化 A，B 置零，所以第 0 轮的模型完全相同。

## 3. 第一部分的方法

部分更新的方法使用 rank16。组件定义为单个投影里某个编号对应的一行（A）或一列（B）：24 个 Q/V 投影各 16 个编号，每次只训练 A 或 B 中的一个，交替进行，共 384 个位置。三档客户端每轮分别更新 96、128、192 个位置。

**挑法：**

- **按分数挑：** 每次参与时用两批 16 条样本求梯度，按“梯度范数除以另一个矩阵对应部分的范数”打分，取最高的若干位置。
- **按顺序轮换：** 每个模块平均分配名额，按客户端累计参与次数轮换编号。
- **整层或按能量挑：** 按层选，或按每个组件外积的大小选。
- **共享梯度摘要后挑：** 客户端上传一份压缩到 32 维的梯度摘要，服务器汇总后，每个客户端按“自己的预测更新在汇总方向上的投影”挑位置。
- **10 个客户端一起挑：** 在上面基础上，服务器在每个客户端的三份候选（按分数、轮换、共享摘要）之间做坐标交换，最大化一个估计的整体损失下降。
- **每轮 A、B 各更新一半位置：** 每轮同时更新两个因子，每个因子用原名额的一半，累计训练的参数量相同。

**拆法**（改变“编号”指的是什么，不改变 B·A 的乘积）：

- **原拆法：** 不变。
- **平衡尺度：** 每个组件把 A 行和 B 列的范数调成相等。
- **SVD 重拆：** B·A 做 SVD，B = U√Σ，A = √Σ Vᵀ。
- **梯度旋转：** 用当前 10 个客户端的梯度摘要求一个正交矩阵 O，令 B' = BO、A' = OᵀA，让靠前的编号对应梯度能量最大的方向。

后三种每 1 轮或 5 轮刷新一次，刷新周期和学习率都在开发阶段比较。

**同名额随机编号对照：** 和“梯度旋转后按分数挑”用同一个种子、同一训练过程中的每模块名额，只把挑中的编号换成随机编号。

**完整 LoRA 和已发表方法：**

- 完整 rank4/8/16：A、B 和分类头同时训练，普通平均。
- 完整 rank16 交替训练：每轮训练 A 或 B 的全部编号。
- Fed-SB、FedSVD、Fed-PLoRA：按原文做法移植到本任务。Fed-SB 用 512 条公共数据初始化，这部分计算和通信照计。

开发阶段 117 种配方的完整参数见 [native_and_recipe_settings.csv](data/1_budget_selection/development/native_and_recipe_settings.csv)。

**验证阶段的 16 个方法按固定规则产生：** 原拆法下的按分数挑和轮换；四种拆法中按分数挑最好的那种，以及它的轮换版本；最好的共享摘要挑法和最好的联合挑法；完整 rank4/8/16 和 rank16 交替；同参数量动作对照中最好的一种；整层或能量中最好的一种；三个已发表方法；同名额随机编号对照。

**诊断：**

- **挑法比较（96 个）：** 从完整 rank16 和 rank16 交替训练的第 10、60 轮保存模型出发，同一批 10 个客户端各自用四种挑法真实训练一轮（按分数、轮换、共享摘要、公共数据梯度方向），记录单个客户端和聚合后在诊断读数集上的损失变化。
- **拆法比较（48 个）：** 在同样的父模型上比较四种拆法以及两种额外处理下，同一批客户端更新的效果。

## 4. 第二部分的方法

客户端照常训练完整 rank8 的 A、B 和分类头。服务器先算普通平均 Ā、B̄、h̄，再按系数 α（LoRA）和 β（分类头）构造候选：

```
A(α) = A0 + α(Ā − A0)
B(α) = B0 + α(B̄ − B0)
h(β) = h0 + β(h̄ − h0)
```

服务器在 512 条公共训练数据上算每个候选的平均交叉熵，选最低的那个，并把它作为下一轮的全局模型。分类头之前的特征只依赖 α，所以每个 α 只需对 512 条样本做一次编码，再用不同的分类头得到所有候选的输出。

| 方法 | 候选 |
|---|---|
| 完整 rank8 | 只有 α = β = 1 |
| 固定缩小分类头更新 | 固定 α = 1、β = 1/4 |
| 整体固定缩小一半 | 固定 α = β = 1/2 |
| 降低客户端分类头学习率 | 客户端上分类头学习率取 LoRA 的 0.1 倍，服务器普通平均 |
| 单系数（4 档 / 17 档） | α = β ∈ {0, 1/4, 1/2, 1}，或 0 到 1 每隔 1/16 |
| 双系数 | α、β 各取 {0, 1/4, 1/2, 1}，共 16 种组合 |
| 双系数分别选 | 在 β = 0 上选 α，在 α = 0 上选 β，再实际评估这个组合 |
| 服务器上训练分类头 | 普通平均后，用 512 条公共样本的缓存特征训练分类头 32 步（batch 16，新建 AdamW） |
| FedLAW | 服务器用公共数据学习客户端权重和整体缩放，一个 epoch |
| FedExP | 按客户端更新的范数自动放大服务器步长 |
| 完整 rank4、Fed-SB | 同第一部分 |

开发阶段每种方法比较了客户端学习率 3e-4 和 1e-3，部分方法还比较了自己的服务器参数，共 32 种配方，每种 4 个种子（503、509、521、541）。每组取开发准确率最高的配方；与最高值相差不到 0.2 个百分点的配方，按种子 503 的计时选更快的。

**诊断（120 个）：**

- 96 个复用第一部分已经训练好的客户端更新（每个对象有按分数挑和轮换两份），只在服务器端按不同规则施加；
- 24 个从完整 rank8 第 10、60 轮的保存模型出发，让 10 个客户端重新训练一轮。

“四角交互”指：同时施加两部分的收益，减去只施加 LoRA 的收益和只施加分类头的收益。负值表示两部分的收益不可直接相加。

**后期不更新比例：** 第 61–100 轮里，服务器提交的参数和上一轮完全相同（按参数哈希判断）的轮次比例。先在每个种子内算，再对 12 个种子平均。

## 5. 第三部分的方法

从单系数（4 档）和双系数各自 12 个验证种子保存的第 60 轮完整状态出发，包括模型参数、服务器缓存和随机数状态。关掉服务器选择，改用普通平均（α = β = 1），续训到第 80 轮。数据、参与顺序、学习率、本地步数都和原轨迹相同。

对照组是原来已经完成的第 61–80 轮轨迹，没有重新训练。主要读数是第 80 轮的准确率和损失，同时报告第 61、65、70 轮。两种控制器分别分析，每组 12 个种子。

## 6. 统计与成本

- **统计单位：** 种子。配对差先在同一种子内相减，再对 12 个种子求平均和 95% t 区间（自由度 11）。检查点、客户端和网格点都不算作独立样本。
- **必要时间：** 生成返回模型所需的全部执行时间，包括客户端训练、打分、服务器决策、编解码和预算控制。研究用的评价、参数滑动平均和保存不计入。
- **计时方式：** 第一部分每种方法用种子 401 在独占的 RTX 4090D 上单独完整跑一次；第二部分用种子 601、607、613 的验证运行时间。两部分都只在同型号独占的显卡上比较，不做跨显卡比较。
- **未测量的项目：** 留空，不按零计。
