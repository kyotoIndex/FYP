PCLA：面向异构联邦 PEFT 的个性化成本感知 LoRA 分配

工作报告

项目方向： 联邦学习、参数高效微调（PEFT）、LoRA、异构客户端资源分配
当前主要实验： SST-2 / BERT-base / 20 客户端 / 部分参与 / Dirichlet 标签异质性
当前建议主线： 组件级 PCLA（pcla_component_alternating）
早期版本： 按层的 PCLA-v1（personalized_cost_aware_lora）

本报告区分 PCLA-v1 与后续组件级 PCLA。二者共享“本地重要性 + 资源预算 + 稀疏分配”的核心思想，但分配粒度和聚合方式不同。

摘要

联邦参数高效微调通常只训练 LoRA 参数，因此比全参数联邦微调更节省通信和计算成本。但是，即使使用 LoRA，不同客户端仍然可能面临不同的算力、内存和通信条件。如果所有客户端训练完整 LoRA，弱客户端会成为同步瓶颈；如果随机删减 LoRA 参数，又可能把训练预算浪费在对当前客户端数据价值较低的参数上。

本项目研究一种个性化、成本感知的 LoRA 分配方法 PCLA（Personalized Cost-aware LoRA Allocation）。PCLA 不改变 BERT backbone，而是在每一轮根据客户端本地数据估计 LoRA 层或组件的重要性，再结合客户端资源预算选择允许训练的部分。早期 PCLA-v1 以完整 LoRA 层为分配单位；当前组件级版本进一步将一个 rank=16 的 LoRA 层拆成多个可对齐的 rank-1 组件，并采用组件级选择、A/B 交替训练和贡献者限定聚合。

在经过全局标签比例修正的 20 客户端、部分参与 SST-2 实验中，PCLA 组件级版本与随机组件方法使用完全匹配的客户端、组件预算、可训练参数量和通信量。PCLA 最终准确率比匹配的随机组件方法高 8.03 个百分点，最后五轮平均准确率高 9.95 个百分点；相对于 Fed-HeLLo，PCLA 最终准确率低 1.39 个百分点，但通信量减少约 74.68%，模拟时间减少约 45.52%。

1. 研究动机

1.1 联邦 PEFT 中的异构资源问题

联邦学习的基本过程是：服务器下发全局模型，客户端使用自己的本地数据进行训练，再向服务器上传模型更新。客户端可能是手机、边缘设备或不同配置的计算节点，因此它们的能力不相同：

  • 弱客户端本地训练速度慢、可用内存少；
  • 网络较差的客户端上传和下载成本高；
  • 客户端之间的本地数据分布不同；
  • 同步联邦学习的轮次时间通常受到最慢客户端影响。

LoRA 只训练低秩适配器，已经降低了联邦微调成本，但完整 LoRA 仍然包含多个 Transformer 层、多个目标投影和多个 rank 方向。如果所有客户端都训练完整 LoRA，则没有利用客户端之间的资源差异；如果简单地删掉一部分层，则可能损失任务相关的更新。

1.2 现有方法的不足

现有方法大致有几种思路：

  1. 完整 FedLoRA： 所有客户端训练全部 LoRA 参数，精度和成本都较高。
  2. 资源分配： 根据客户端能力决定训练多少层，但不一定知道哪些层对当前任务更有价值。
  3. 随机部分分配： 在预算内随机选择层或组件，成本较低，但选择可能不匹配本地数据。
  4. 全局重要性分配： 服务器使用 proxy 数据估计一套全局层重要性，客户端共同参考这套重要性。
  5. 结构化 rank/depth 分配： 预先设计 rank 或网络深度的分布，再按照客户端完成时间或资源能力决定训练范围。

本项目关注的问题是：

在不同客户端具有不同计算和通信预算、且本地数据分布不一致的情况下，能否根据客户端特定的边际重要性，在固定资源预算内选择更值得训练的 LoRA 层或组件？

1.3 为什么选择 SST-2 作为第一阶段验证任务

SST-2 是一个公开的二分类情感分析数据集，任务和模型规模相对可控，适合先验证分配机制、预算匹配和聚合正确性。本项目将 SST-2 的训练样本人为划分到多个模拟客户端中，模拟客户端级标签异质性和资源异构。

但是，SST-2 的任务较简单，当前实验主要验证的是标签偏斜场景下的分配机制，不能单独证明 PCLA 对所有复杂非 IID 任务都具有普适优势。后续需要增加多分类任务、不同异质性强度和更丰富的特征分布差异。

2. 数据角色与联邦实验建模

2.1 “本地数据”与“服务器 proxy 数据”

SST-2 本身没有天然的“公共数据集”和“本地数据集”。本项目使用同一个公开数据集，但按照联邦实验中的用途进行划分：

SST-2 train.tsv
        └── 划分为多个客户端的本地训练数据

SST-2 dev.tsv
        ├── 320 条 server proxy 数据
        └── 552 条独立评估数据

在当前大规模组件实验中：

  • 20 个模拟客户端；
  • 每个客户端 512 条本地训练样本；
  • 每轮随机选择 10 个客户端；
  • 客户端训练样本无重复使用；
  • 使用约束 Dirichlet 标签异质性，使客户端标签分布不同，但所有客户端合起来仍保持 SST-2 的总体标签比例。

server proxy 主要用于 Fed-HeLLo、FIM-HLA 等服务器侧全局重要性方法。PCLA 的个性化重要性使用对应客户端的本地训练数据计算。在单机实验代码中，runner 能访问所有客户端数据 loader，这是对多客户端系统的集中式模拟；真实联邦部署时，原始客户端数据应留在客户端。

2.2 客户端与资源能力

当前实验不是实际连接 20 台设备，而是用配置模拟三种资源档位：

能力档位 客户端比例 最大 active layer 数 组件级预算（每层 8 个组件） compute factor communication factor
Low 60% 6 48 1.8 1.3
Medium 30% 9 72 1.2 1.0
High 10% 12 96 0.7 0.8

这里的能力通过配置化预算和时间因子实现：

  • 预算决定训练多少： 低、中、高能力客户端分别最多训练 6、9、12 个 active layers；组件级版本每个 active layer 训练 8 个 rank 组件。
  • 时间因子决定同样工作量需要多久： 本地测得的训练时间乘以 compute factor，通信量再乘以通信时间系数和 communication factor。

当前实验验证的是资源预算约束下的分配机制，不是实际设备在线 benchmark 后动态调度的完整系统。

组件的位置由以下信息确定：

Transformer 层编号 + 目标投影（query/value）+ rank 编号

所谓“自动对齐”不是语义匹配算法，而是因为所有客户端使用相同模型结构、相同 rank 和相同目标模块，所以相同位置的组件天然对应。服务器可以直接聚合同一层、同一目标模块、同一 rank 编号的参数。

4. 方法设计

4.1 方法总流程

每个稀疏训练轮次可以概括为：

服务器下发当前全局 LoRA 状态
        ↓
客户端用本地 batch 估计层/组件重要性
        ↓
EMA 平滑并加入探索、新鲜度等选择项
        ↓
根据客户端预算选择层或组件
        ↓
本地训练选中的 LoRA 参数
        ↓
服务器只聚合真正更新过相应参数的客户端

4.2 重要性估计

层级 PCLA-v1

对客户端 kkk 的第 lll 层，使用本地数据计算 LoRA 梯度范数作为重要性近似：

Ik,l=∥∇LoRAk,lLk∥2I_{k,l}=\left\|\nabla_{\mathrm{LoRA}_{k,l}}\mathcal L_k\right\|_2Ik,l​=​∇LoRAk,l​​Lk​​2​

直观解释是：如果本地 loss 对某一层的参数更敏感，那么该层的梯度通常更大，训练该层可能具有更高的短期边际价值。

PCLA-v1 先得到客户端层重要性，再计算 cluster mean importance，并用客户端特定的计算和通信成本进行层选择：

scorek,l=Icluster(k),lCostk,lscore_{k,l}=\frac{I_{cluster(k),l}}{Cost_{k,l}}scorek,l​=Costk,l​Icluster(k),l​​

当前 PCLA-v1 的聚类规则是启发式的，并不是真正基于原始文本或语义嵌入的 K-means 聚类。主实验显示，它主要分出了资源层级，不能宣称已经学到了清晰的数据语义簇。

组件级 PCLA

组件级版本分别考虑当前要训练的 LoRA 因子。

当训练 BBB、冻结 AAA 时，组件 jjj 的原始重要性为：

Ik,l,j(A)=∥B:,j∥2∥∇Aj,:Lk∥2I^{(A)}_{k,l,j} = \left\|B_{:,j}\right\|_2 \left\|\nabla_{A_{j,:}}\mathcal L_k\right\|_2Ik,l,j(A)​=∥B:,j​∥2​​∇Aj,:​​Lk​​2​

代码在 query 和 value 投影上累加同一层、同一 rank 组件的贡献。这个分数是基于梯度的局部敏感性近似，不是对长期最终收益的精确估计。

4.3 EMA、探索和新鲜度

为了避免重要性被单个 batch 的噪声支配，PCLA 使用 EMA：

Iˉk,c,t=ρIˉk,c,t−1+(1−ρ)I~k,c,t\bar I_{k,c,t} = \rho\bar I_{k,c,t-1} +(1-\rho)\tilde I_{k,c,t}Iˉk,c,t​=ρIˉk,c,t−1​+(1−ρ)I~k,c,t​

  • Z(Iˉ)Z(\bar I)Z(Iˉ)：标准化后的长期重要性，是主要依据；
  • Nk,c,tN_{k,c,t}Nk,c,t​：组件过去被选择的次数，被选越少，探索奖励越大；

探索和新鲜度的目的都是防止组件过早淘汰，但侧重点不同：探索看历史选择次数，新鲜度看距离上次选择多久。

4.4 组件选择策略

当前每个客户端每个 active layer 选择 8 个组件。选择过程不是把全模型所有组件简单排序，而是：

  1. 对每一层取分数最高的 8 个组件，计算这一层的代表分数；
  2. 按层代表分数选择客户端容量允许的层数；
  3. 每个入选层至少保留一个最高分组件；
  4. 在入选层内按组件分数填满总预算。

这样可以同时保留层覆盖和组件级灵活性，避免所有预算集中到少数 Transformer 层。

4.5 A/B 交替训练

一个组件由 AAA 的一行和 BBB 的一列共同构成。组件级版本采用：

奇数稀疏轮：训练 B，冻结 A
偶数稀疏轮：训练 A，冻结 B

冻结表示这一轮参与前向计算但不接收有效梯度更新，不表示删除参数或把参数置零。这样每轮只需要训练和上传一半 LoRA 因子，降低可训练参数和通信量。被冻结的因子需要在客户端缓存；当前通信估算明确包含这一缓存假设。

4.6 贡献者限定聚合

对于组件 ccc，定义本轮真正训练它的客户端集合：

服务器只对 Cc,t\mathcal C_{c,t}Cc,t​ 内的客户端进行样本量加权平均：

如果本轮没有客户端训练组件 ccc，则保留上一轮全局值。没有训练某组件的客户端不会因为拥有旧副本而参与该组件的平均。

6.2 对比方法

主组件级实验包括：

  • FedLoRA：完整 LoRA；
  • Fed-HeLLo：资源能力与服务器 proxy 全局重要性；
  • Random Component Alternating：与 PCLA 完全匹配预算的随机组件控制；
  • PCLA Component Alternating：本地重要性、EMA、探索/新鲜度和组件级分配。

其中 PCLA 与 Random Component 的公平性约束为：

  • 同一批选中客户端；
  • 同一客户端容量；
  • 同一 active component 数量；
  • 同一训练 A/B 因子；
  • 同一可训练参数量；
  • 同一通信量；
  • 同一聚合规则。

因此，两者的主要差异是组件选择策略。

7. 实验结果

7.3 与 Fed-HeLLo 和完整 FedLoRA 的效率—准确率权衡

相对于 Fed-HeLLo，PCLA：

  • 最终准确率低 1.39 个百分点；
  • 最后五轮平均准确率低 3.02 个百分点；
  • 全轮平均准确率低 2.30 个百分点；
  • 通信量减少约 74.68%；
  • 模拟时间减少约 45.52%。

相对于完整 FedLoRA，PCLA：

  • 最终准确率低 2.42 个百分点；
  • 通信量减少约 84.40%；
  • 模拟时间减少约 68.09%。

重要性估计本身平均增加约 25.61 秒，占 PCLA 模拟总时间约 25.56%。即使计入这部分开销，PCLA 在该实验中仍比 Fed-HeLLo 更省时，但重要性估计成本是后续优化重点。

7.5 组件级 PCLA 与经典 baseline 的关系

两组实验需要分开解释：

  1. 经典 baseline 全面对比： 统一比较多种已有分配思想，PCLA-v1 的分配单位是完整层。
  2. 组件级受控对比： 重点验证组件级 PCLA 是否比相同预算的随机组件选择更有效。

这样做是因为组件级 PCLA 的核心问题不是重新和所有方法做一组不匹配的比较，而是先回答一个更直接的问题：

在通信量、可训练参数量和客户端预算都完全相同的情况下，基于本地重要性的组件选择是否优于随机组件选择？

当前答案是肯定的：组件级 PCLA 比匹配随机组件方法高 8.03 个百分点的最终准确率。但它仍然没有在准确率上超过完整 FedLoRA 或 Fed-HeLLo，因此应当报告为精度—效率折中，而不是全面优越。

图 5：组件级 PCLA 与完整 LoRA、Fed-HeLLo 的准确率—通信量关系

图中可以直接看到：PCLA 与随机组件方法位于相同通信预算，但 PCLA 准确率明显更高；完整 FedLoRA 和 Fed-HeLLo 使用更多通信换取更高准确率。

7.5 数据划分修正的必要性

早期组件实验曾独立为每个客户端采样标签比例，导致某些 seed 的客户端总体几乎全是负类，分类器接近恒预测负类的准确率 0.4928。后续修正版同时保持：

  • 每个客户端固定样本数；
  • 客户端之间存在标签异质性；
  • 所有客户端合起来保持原始 SST-2 标签比例；
  • 不重复使用源数据。

因此，早期未修正实验不能与修正版主结果混合报告。当前正式组件结论应以全局标签比例保持的结果为准。

8. 方法优势、劣势与原因

8.1 优势

（1）相同预算下优于随机选择

PCLA 和 Random Component 的可训练参数量、通信量和客户端参与情况严格匹配，PCLA 的准确率提升主要来自选择策略，而不是使用更多资源。

（2）比完整 FedLoRA 更节省通信

客户端不需要训练和上传完整 LoRA，只上传本轮真正训练的组件。A/B 交替进一步减少单轮训练因子数量。

（3）适应客户端能力差异

弱客户端训练更少的 active layers/components，强客户端可以训练更多，从而避免所有客户端被同一个完整 LoRA 预算约束。

（4）比全局重要性更具有客户端针对性

Fed-HeLLo 主要使用服务器 proxy 数据得到一套全局层重要性；PCLA 使用客户端本地数据维护客户端特定的重要性状态，因此理论上可以适应不同客户端的局部数据需求。

（5）适合部分重叠更新

贡献者限定聚合避免未更新组件的旧参数稀释真正的本轮更新。

8.2 劣势和限制

（1）重要性估计有额外开销

PCLA 需要额外的本地 batch 反向传播来计算重要性。当前大规模实验中，重要性估计约占模拟总时间的 25.56%。

（2）梯度重要性只是局部近似

梯度大表示当前模型和当前 batch 对某个组件较敏感，但不保证该组件对长期最终准确率一定最有价值。梯度还会受到 batch 噪声、当前模型状态和标签异质性的影响。

（3）SST-2 的外部有效性有限

当前证据主要来自 SST-2、BERT-base、三种随机种子和一种 Dirichlet 标签异质性。二分类短文本任务不能代表所有多分类、长文本或跨领域联邦任务。

（4）当前资源能力是模拟的

compute factor、communication factor 和 active-layer capacity 是协议配置，而不是从真实设备在线测量得到的动态资源预算。

（5）当前组件稀疏主要是逻辑稀疏

代码通过 mask 控制有效更新和通信统计，但底层矩阵运算仍可能以 dense rank=16 形式执行。因此当前结果最稳妥地支持“可训练参数和通信量减少”，不能直接等同于真实 GPU 计算量按同样比例减少。

（6）组件不是天然具有独立语义

一个 rank 组件是 A 的一行和 B 的一列组成的低秩方向，并不一定对应一个可解释的语义功能。组件级方法的价值来自更细粒度的预算控制和经验上的选择效果，而不是每个组件都具有清晰的人类语义。

10. 后续工作

10.1 更真实的动态资源预算

让客户端通过短 benchmark 或历史运行统计得到：

  • 每秒训练 batch 数；
  • 可用内存；
  • 上下行带宽；
  • 单轮最大允许时间。

然后将能力转换为计算和通信预算，动态决定本轮可以训练多少组件，而不是只使用固定 low/medium/high 档位。

10.2 降低重要性估计成本

可以测试：

  • 更低的刷新频率；
  • 更少的 importance batches；
  • 只在客户端首次参与或状态变化明显时刷新；
  • 用低成本 proxy 或上一轮梯度近似；
  • 将重要性估计与正常本地训练反向传播合并。

10.3 扩展任务与异质性

需要加入：

  • AG News 等多分类任务；
  • 多个 Dirichlet alpha；
  • 标签比例接近但文本特征不同的划分；
  • 不同模型和不同 LoRA rank。

10.4 更严格的组件消融

需要分别验证：

  • 只做组件分解、不做重要性；
  • 本地重要性与全局 proxy 重要性；
  • EMA 的作用；
  • 探索项和新鲜度项的作用；
  • A/B 交替与同时训练的差异；
  • 贡献者限定聚合与普通聚合的差异。

10.5 更严格的优化建模

当前选择器主要使用固定容量和启发式分数。后续可将计算、通信和客户端截止时间写成显式约束，并联合决定：

  • active layers；
  • 每层 rank/components；
  • 客户端参与与否；
  • 聚合权重和稳定性约束。
