# C2-0 结果的相关工作核对：别人是否遇到过类似情况

日期：2026-10-18。上游：[C2-0 设计与结果 §10](c2_0_probe_design_2026-10-18.md)。这是一次聚焦的检索（通用网页搜索，读了摘要和综述页面），没有逐篇读全文；凡是没有核实的地方都已标出。

## 1. 要回答的两个问题

1. 我们推测"在固定的每分量缩放下，R = 64 的完整训练本地步子太大"，这有没有已知的理论或观察？
2. 别人在异构 rank 的联邦 LoRA（尤其是大模型）上，有没有报告过类似的不稳定或掉点？他们怎么解释？

## 2. 问题一：大 rank、固定缩放时的不稳定，是已知现象

| 工作 | 内容 | 与我们的关系 |
|---|---|---|
| [rsLoRA](https://arxiv.org/abs/2312.03732)（Kalajdzievski，2023） | 在 B 初始化为 0、A 独立同分布的假设下证明：只有当缩放系数 γ_r ∈ Θ(1/√r) 时，各 rank 的学习才是稳定的；否则 rank 足够大时，学习会不稳定或塌缩。标准的 α/r 缩放会塌缩，所以提出 α/√r（PEFT 中的 `use_rslora`） | **直接支持我们的推测。** 我们用的是每个分量固定的缩放（γ = 2，不随 R 变），属于 rsLoRA 所说"rank 大时不稳定"的一侧：R 越大，完整训练每步的函数变化越大。R = 8（RoBERTa）时问题不明显，R = 64（Qwen）时就显现出来，这与"完整训练的本地损失反而高于受限训练"一致 |
| [Learning Rate Scaling across LoRA Ranks and Transfer to Full Finetuning](https://arxiv.org/abs/2602.06204)（Chen、Villar、Hayou，ICML 2026） | 提出 μA：按 μP 的思路分析最优学习率如何随宽度和 rank 变化。结论是存在两种区间：一种最优学习率与 rank 无关，另一种与 rank 成反比，取决于初始化和缩放系数。分析用 SignSGD 近似 Adam | **同时支持两件事**：(1) 在我们的缩放下，最优学习率应随 R 减小，R = 64 时沿用为 R = 8 调的 2e-4 很可能偏大；(2) 在 Adam 类优化器下，每步的特征变化与"参与训练的分量数 × 缩放"成正比，这正是放大前向 α = R/r 的理论基础（文献核对中已提到） |
| [Function-Space Learning Rates](https://arxiv.org/abs/2502.17405) | 在 Adam 下按 rank 和参数分别扫学习率，关注函数空间里的更新大小 | 与我们用函数空间步长做诊断的思路一致；没有讨论只训练部分分量的情形 |

**结论：** "R = 64 时参照训练本身步子太大"不是我们独有的猜测，而是 rsLoRA 和 μA 理论预言的现象。C2-1 必须先处理这一点：要么按 rank 调小学习率，要么改用 rsLoRA 的缩放。否则参照（完整训练）和我们的方法都在不稳定的区间里比较。

## 3. 问题二：异构 rank 联邦 LoRA 的不稳定，已有报告，但解释都不在本地训练动态上

| 工作 | 报告的现象 | 他们的解释 | 与我们的区别 |
|---|---|---|---|
| [Towards Federated LoRA with Rank Heterogeneity](https://arxiv.org/abs/2406.17477)（2024） | LoRA 的表现对 rank 异构**高度不稳定**；零填充聚合在客户端数据质量不同时可能不如同质 LoRA | 零填充把高 rank 客户端的信息稀释了，提出复制填充 | 归因于聚合方式 |
| [raFLoRA](https://arxiv.org/abs/2602.13486)（2026） | "rank 塌缩"：全局更新的能量集中到最小的共享 rank，表现次优、对 rank 设置敏感 | 与 rank 无关的聚合权重和与 rank 有关的客户端贡献不匹配，高 rank 的更新以几何速度被压制；按 rank 分区聚合 | 归因于聚合权重（我们的 Hájek 处理的就是这一类问题） |
| [Fed-PLoRA](https://arxiv.org/abs/2602.16936)（ICLR 2026） | 已有方法存在初始化噪声和聚合噪声 | HetLoRA 截断、FLoRA 每轮随机重新初始化都会引入初始化噪声；用并行单 rank 模块 + Select-N-Fold | 归因于初始化与聚合；其结构就是我们的 L2 / hajek 基线 |
| [ILoRA](https://arxiv.org/abs/2511.16069)（2025） | 随机初始化导致客户端子空间不对齐，引起不稳定 | 用 QR 正交初始化 | 归因于初始化 |
| [LoRA-A²](https://aclanthology.org/2025.acl-long.19)（ACL 2025） | 已有方法在低 rank、强异构时退化 | 交替冻结 + 自适应 rank 选择 | 归因于聚合失配 |

**结论：**
1. **"异构 rank / 部分分量训练会不稳定、会掉点"已经被多篇工作观察到**，包括大模型上的实验。所以 C2-0 的现象并不意外，反而与文献一致。这也加强了我们问题的重要性。
2. **这些工作都把原因归于聚合、初始化或填充方式**，没有找到把原因归于"只训练部分分量时，本地训练动态在 Adam 下偏离完整训练"的工作。我们的诊断（vref 证明聚合与通信不是瓶颈、D2 / D3 / C2-0 定位到本地动态）与它们是互补的，这一点仍然是新的。
3. 检索没有找到"只训练部分 rank 分量时按比例放大"的直接先例，与之前的文献核对（最接近的是 FSLoRA）一致。

## 4. 对 C2-1 设计的影响

1. **先确定参照训练的学习率。** 按 μA 的结论，在我们固定缩放的设定下，最优学习率应随 R 减小。C2-1 先在开发 seed（2041）上对同质 R = 64 的完整训练扫几个学习率，按核心弱端准确率选择（规则事先写定，见 C2-1 设计 §3），再用选出的学习率跑主实验（seed 2040）。本地损失的对比只作为诊断项记录。
2. **不改缩放方式。** 改成 rsLoRA 会同时改变 RoBERTa 那边的可比性；按 rank 调学习率在 Adam 下与改缩放大致等价，而且更简单。这一点在论文中要说明。
3. **主实验仍然比较 r8、L2、vref、amp。** 判读同时看后期和冷启动阶段，因为 C2-0 显示冷启动是放大前向最弱的地方。
4. **论文表述：** 现象（异构 rank 不稳定）是已知的；我们的贡献在于把原因定位到本地训练动态，并给出从源头修正的方法。

## 5. 局限

- 只读了摘要、综述页面和检索摘要，没有逐篇读全文；rsLoRA 和 μA 的具体条件（初始化、优化器近似）与我们的设定是否完全一致，没有逐条核对。
- 没有找到专门研究"冻结部分 rank 分量的 LoRA 训练"的工作；Partial-LoRA（[arXiv 2512.22495](https://arxiv.org/abs/2512.22495)）是按子网络选择参数，不是按 rank 分量冻结。
