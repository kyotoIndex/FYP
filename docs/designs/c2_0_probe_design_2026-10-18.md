# C2-0 机制探针设计：解码器大模型上是否同样存在受限训练过冲

日期：2026-10-18。状态：**代码已写（scra/llm.py、scra/c2probe.py），交接文档见实验目录 HANDOFF_C2_0_ASSETS.md。** 写代码时修正了单个客户端的比较口径（§4、§5 的 M1）。按就绪度评估补充了：身份与哈希记录、缓存与数据校验、断点续跑、可学习性门槛（§5）、M2 的逐轮统计，以及 c2check 落盘。本探针不测资源节省。 上游：[路线图](roadmap_2026-10-18_amplified_restricted.md) 阶段 C2、[资源核算](resource_case_2026-10-18.md) §5、[研究文档 §5–§8](research_two_directions_2026-10-17.md)。

## 1. 要回答的问题

在一个**没有从零训练的分类头**的解码器模型上：
1. 受限训练（只训练 R 个分量中的 r 个）是否仍然沿完整训练方向过冲？拼接（聚合）后是否仍然放大？
2. 放大前向（α = R/r）是否仍能让每个客户端的位移、拼接后的步长回到完整训练的水平？
3. 聚合一步后，准确率上是否能看到受限训练的损失，以及放大的修复？

这是一个**只看一步**的诊断（与 D2 / D3 的协议相同）。它只判断机制是否存在、修复方向是否正确，**不**判断最终能提升多少；后者属于 C2-1 / C2-2。D3 的一步结论在 RoBERTa 上已被多轮训练全部证实，但"这一步不更新头部"的例子说明一步视角会漏掉多轮效应。

## 2. 为什么选这个设定

| 选择 | 内容 | 理由 |
|---|---|---|
| 模型 | **Qwen2.5-0.5B Base**（tied embeddings，24 层，hidden 896，intermediate 4864，KV 头 2 个） | 最便宜的解码器模型；项目协议已把 Qwen2.5 列为生成式扩展；C1 的核算覆盖它 |
| 任务 | **MNLI 改写为下一个词预测**：提示词 + 标签词（" yes" / " maybe" / " no"），训练用全词表交叉熵（只在答案位置），评测用这三个词的 logits 取最大 | 沿用**同一份数据划分**（manifest seed2026 的 50 个按 genre 划分的客户端）、同一组强端 {10, 11, 12, 40, 41} 和 30 个核心弱端，结果可以直接对照 RoBERTa。没有从零训练的新分类头（冻结的输出词嵌入仍然参与前向和损失计算），正好检验"没有新头时会怎样" |
| LoRA | 每层全部 7 个线性层（q、k、v、o、gate、up、down），**R = 64，r = 8，α = 8**，缩放常数 2（相当于 lora_alpha = 128） | C1 的结论是 R = 64 时资源差异最大；α = 8 在 RoBERTa 上已经验证过（r = 1 时追回比例 1.01） |
| 本地训练 | AdamW，lr 2e-4，20 步，批大小 8，最长 256 个 token，梯度裁剪 1.0 | 与 RoBERTa 实验一致，只改模型和任务 |
| 联邦 | 每轮 10 个客户端，seed 2040 的参与者日程，10% 强端 | 与 RoBERTa 一致 |

**提示词模板**（定稿前在 tokenizer 上确认三个标签词各是一个 token；如果不是，改用 " true" / " neither" / " false" 等单 token 的词）：

```
Premise: {premise}
Hypothesis: {hypothesis}
Does the premise entail the hypothesis? Answer:{label_word}
```

## 3. 协议

**第一步：生成状态快照。** 跑一个短的同质 rank-64 FedAvg（所有人完整训练），30 轮，在第 0、5、30 轮保存全局状态。用中性的 r8 轨迹，而不是受限训练的轨迹，避免状态本身已经被某种方法扭曲。第 0 轮是冷启动（B = 0）。

**第二步：在每个快照上模拟 12 轮。** 参与者和分量分配都用快照之后真实轮次的日程。每个参与者在同一批数据上：
- 完整训练（全部 64 个分量）；
- 若是弱端，再做受限训练（覆盖均衡分配的 8 个分量）和放大受限训练（同样的 8 个分量，α = 8）。

**第三步：各规则只更新一步，然后评测。**

| 规则 | 内容 |
|---|---|
| r8 | 所有人完整训练，所有分量加权平均 |
| vref | 完整训练，弱端只贡献分配到的分量，Hájek |
| L2 | 受限训练，拥有者平均 |
| hajek | 受限训练，Hájek |
| **amp** | 放大受限训练，Hájek |

## 4. 测量

| 层面 | 量 | RoBERTa 上的对应值 |
|---|---|---|
| 单个弱端（只看分配到的分量） | 受限 / 放大的乘积空间位移，与该客户端完整训练**限制到同一组分量**后的位移比较：沿后者的步长和余弦（实现：`restrict_to_sets`；若与全部分量的完整位移比较，即使完全正确也只有约 r/R） | 受限：余弦 0.89–0.93，范数比 1.08–1.15；放大：0.99–1.00、1.00（D3） |
| 单个弱端（函数空间） | 在一个固定的探测批上，三个标签词对数概率的变化沿完整训练方向的投影：⟨Δ_x, Δ_full⟩ / ‖Δ_full‖²。逐个分量都匹配完整训练时约为 r/R，过冲时更大 | 新增：没有头时，这是"函数被推了多远"最直接的量 |
| 聚合后 | 乘积空间 ΔW 沿 r8 均值方向的步长、偏差²、配对误差（D2 / D3 的 `dispersion`） | hajek 1.69–1.86，L2 1.55–1.70，amp 1.00（D2 / D3） |
| 聚合后（函数空间） | 同样的 logits 投影，用聚合后的模型 | 新增 |
| 一步后的准确率 | 核心弱端准确率和 NLL，与同一轮的 r8 配对相减；验证集每个客户端最多取 40 条（约 2000 条） | hajek −4.45 到 −12.09，amp −0.00（D2 / D3，第 120 / 20 轮） |
| 本地训练 | 三种训练方式的平均本地损失 | — |

## 5. 事先写定的判读（3 个快照中至少 2 个满足）

| 编号 | 问题 | 判据 |
|---|---|---|
| **M0** | 没有新分类头时，受限训练仍然过冲 | hajek 聚合后沿 r8 的乘积空间步长 ≥ 1.2，或函数空间步长 ≥ 1.2 |
| **M1** | 放大仍能修正 | amp 聚合后步长在 [0.9, 1.1]，且单个弱端在分配到的分量上，放大位移沿完整位移的步长中位数在 [0.95, 1.05]、余弦中位数 ≥ 0.95 |
| **M2** | 一步后能看到准确率上的损失和修复 | L2 或 hajek 的核心弱端差值 ≤ −0.5pp，且 amp 与 vref 相差 ≤ 0.2pp |

**可学习性门槛**（按 [就绪度评估](../../federated_finetuning/experiments/scra_diagnostics_20261017/C2_0_PROBE_READINESS_REVIEW_2026-10-18.md) P0-4 补充，运行前固定）：只有更新前核心弱端准确率 ≥ 45%（比三分类随机水平高 10pp 以上）的快照才参与 M2 的判读；没有快照通过时，M2 记为"无法解读"，要先检查提示词和标签词或延长快照训练。M0、M1 是更新量层面的测量，不受门槛限制。M2 同时报告每轮模拟的配对差值、正负方向计数；只有少数几轮同向的边缘结果不算强结论。

| 结果 | 含义 | 下一步 |
|---|---|---|
| M0 与 M1 都成立 | 机制和修复在解码器大模型上同样存在 | 进入 C2-1（提升空间的短联邦训练） |
| M0 成立，M1 不成立 | 存在过冲，但 α = R/r 的推导在大模型上失效（例如"分量可互换"不成立） | 先检查单个客户端的探针，弄清是哪个假设失效，再决定是否修改方法 |
| M0 不成立 | 没有新分类头时，受限训练不会明显过冲 | 论文明确适用范围：有共同训练的新参数（如分类头）的设定。C2-1 可以只做提升空间检查，确认受限训练在大模型上确实没有损失 |
| M2 不成立，但 M0 / M1 成立 | 机制存在，但单步准确率上看不出来（提升空间可能很小） | 进入 C2-1，重点看多轮训练和提升空间 |

## 6. 成本估计

- 状态快照：30 轮 × 10 个客户端 = 300 次本地训练，加 4 次评测。
- 探针：3 个快照 × 12 轮 × 约 28 次本地训练（10 次完整 + 9 次受限 + 9 次放大）≈ 1000 次本地训练；每轮 5 条规则的评测（约 2000 条）。
- Qwen2.5-0.5B、LoRA R = 64、序列 ≤ 256、批大小 8、20 步，在 4090 上估计每次本地训练 3–5 秒。**合计约 2–2.5 GPU 小时**，可以按快照拆成 3 个数组任务。
- 显存：主干 bf16 约 1 GB，加 LoRA R = 64 训练状态约 0.5 GB，加激活（序列较短）。单卡 4090 足够。

## 7. 实现要点（写代码时遵守）

1. **分块要支持不等宽。** 7 种线性层的 d_in + d_out 不同（q：896 + 896；k / v：896 + 128；gate / up：896 + 4864；down：4864 + 896），不能像 RoBERTa 那样堆成一个 [J, R, D] 张量。按适配器存成列表，或按 (d_in, d_out) 分组；聚合、分配、Hájek 逻辑不变。
2. **复用 scra 中已经测试过的部分：** 覆盖均衡分配、block_aggregates 的数学、放大前向（LoRALinear.amp）、dispersion。新的 LLM 模型包装放在单独的模块里，RoBERTa 的代码不改。
3. **主干用 bf16，LoRA 参数和 Adam 状态用 FP32。** 放大前向的 detach 技巧同样适用。
4. **显存实测留到 C2-2。** 当前实现把未训练分量保留为参数、只把梯度清零，AdamW 仍会为它们分配状态，所以测不出 C1 估计的节省。C2-2 要把未训练分量折进冻结权重后再实测。
5. **测试：** 在一个随机初始化的小 Qwen2 配置（2 层、hidden 64）上做 CPU 单元测试，检查：
   - 放大前向 α = 1 时与普通受限训练逐位相同；
   - 只有分配到的分量会动；
   - 冷启动时 vref 与 r8 在所有客户端都完整训练、全覆盖的情况下一致；
   - 标签词都是单 token。

## 8. 需要在 HPC 上准备的资源（由用户在有网络的节点上完成）

1. 下载 Qwen2.5-0.5B（固定 revision）到 `federated_finetuning/models/qwen2.5-0.5b`，例如用项目里的 `hpc/cache_model.py` 或 `huggingface-cli download Qwen/Qwen2.5-0.5B --revision <commit>`。
2. 确认 `federated_finetuning/data/mnli_r1_seed2026/train.jsonl` 和 `validation.jsonl` 在 HPC 上存在，并且行里有 `text`、`text_pair` 字段（`fedft/data.py` 写出的格式就是这样）。新的 Qwen token 缓存由探针代码在第一次运行时根据这两个文件生成，下标与 manifest 一致。

## 9. 不能从这个探针得出的结论

- 最终准确率能提升多少（需要 C2-1 / C2-2）；
- 多轮训练中误差是否累积；
- 大模型上的显存节省（需要 C2-2 的折叠实现）；
- 生成任务上的表现：这里的 MNLI 只是下一个词预测的分类，不能代表通用的生成或指令能力。

## 10. 结果（2026-10-18）

报告：`federated_finetuning/runs/c2_probe_20261018/diagnostics_report/REPORT_C2_0.md`。本地用原始数据重新计算过，判读一致。三个探针的代码哈希与本地相同；模型版本 `060db6499f32faf8b98477b0a26969ef7d8b9987`；快照哈希与探针读取的一致。快照运行中全体 / 核心弱端准确率：第 0 轮 58.25 / 57.75，第 10 轮 81.45 / 80.08，第 30 轮 83.65 / 82.50。

| 快照 | hajek 聚合（乘积步长 / 函数步长 / 函数余弦） | amp 聚合（乘积步长 / 函数余弦） | vref 函数余弦 | 单客户端（分配到的分量，乘积步长 / 余弦）受限 → 放大 | 一步后核心弱端差值（pp）：L2 / hajek / amp / vref |
|---|---|---|---|---|---|
| 0（冷启动） | 0.83 / 1.02 / 0.77 | 0.96 / 1.00 | 1.00 | 0.41 / 0.41 → 0.79 / 0.79 | −17.97 / −21.01 / **−6.30** / −0.47 |
| 5 | 0.72 / 2.53（单轮从 −0.44 到 5.46）/ 0.54 | 0.93 / 0.89 | 0.95 | 0.66 / 0.62 → 0.90 / 0.90 | −6.90 / −12.26 / **−0.14** / −0.17 |
| 30 | 0.79 / 1.12 / 0.51 | 0.96 / 0.90 | 0.93 | 0.79 / 0.74 → 0.94 / 0.94 | −3.42 / −4.45 / **−0.33** / −0.33 |

amp − vref（核心弱端，配对）：第 0 轮 −5.83（11 轮为负），第 5 轮 +0.03（6−/6+），第 30 轮 +0.01（4−/6+）。L2 和 hajek 在所有快照上几乎每轮都为负（12/12 或 10–11/12）。

**事先写定的判读：** M0 不成立，M1 不成立，M2 成立（3 个快照都通过可学习性门槛）。

**解读：**
1. **受限训练的损失在解码器大模型上同样存在，而且更大**：没有从零训练的新分类头，一步后核心弱端仍掉 3–21pp，几乎每轮都为负。问题不依赖分类头。
2. **但形式与 RoBERTa 不同，事先写定的"过冲"判据不成立。** 受限聚合在乘积空间里沿 r8 的步长小于 1（0.72–0.83），而不是 RoBERTa 上的 1.5–1.9 倍。损失来自**方向偏离**：函数空间余弦只有 0.51–0.77（vref 为 0.93–1.00），第 5 轮函数步长在各轮之间剧烈波动（−0.44 到 5.46），对应 RoBERTa 上的摆动。单个客户端在分配到的分量上，受限位移也更小、方向偏离更大（余弦 0.41–0.74）。
3. **训练一段时间后，放大能修复准确率损失**：第 5、30 轮 amp 与 vref 的配对差值为 +0.03、+0.01pp，函数余弦恢复到 0.89–0.90。但单客户端的匹配度（余弦 0.79–0.94）没有达到事先写的 0.95，M1 按判据不成立。
4. **冷启动时放大只能部分修复**（−6.30 对 vref −0.47；12 轮中有 4 轮掉 9–20pp）。
5. **一个值得注意的现象（推测，未验证）：** 在冷启动和第 5 轮，完整训练的本地平均损失**高于**受限训练（1.95 对 1.22；0.90 对 0.56），而放大训练与完整训练一致。在固定的每分量缩放（scale = 2）下，R = 64 时完整训练每步的函数变化约是 R = 8 时的 8 倍，本地可能处于步长偏大、来回震荡的区间。放大训练复制了这种动态，这可能是冷启动时修复不完全、单客户端匹配度偏低的原因。

**对路线的含义：** 事先写定的决策表没有覆盖"M0、M1 不成立而 M2 成立"的情况，这里如实记录，不事后改判据。
- 方法层面：在热身之后的快照上，放大在准确率上完全追平 vref，所以值得进入多轮验证（C2-1）。
- 机制层面：论文中"过冲"的说法只适用于 RoBERTa。更一般的表述应当是"受限训练的本地动态偏离完整训练，拼接后进一步放大"；大模型上表现为方向偏离和不稳定，而不是步长过大。
- C2-1 开始前，应先做一个小的学习率检查，避免参照（完整训练）本身处在步长偏大的区间。**最终规则见 [C2-1 设计](c2_1_design_2026-10-18.md) §3：按第 10 轮核心弱端准确率选学习率；"完整训练的本地损失不高于受限训练"作为诊断项记录，不作为选择规则。**（此处最初写的是按本地损失选，与 C2-1 设计不一致，已统一。）
